## Decisions already made (coordinator)

- umem_sm_* exports: DROP sm.c/sm.h from libumem_la_SOURCES. No libumem code
  has ever called them, no header is installed, no documented contract, and
  they put ~55 KB of dead executable code into every LD_PRELOAD target.
  Delete sm.c/sm.h and the dead test/common.[ch] from the tree (nothing uses
  them; git history keeps them). Bump -version-info to signal the removed
  interfaces (libtool: current+1, revision=0, age=0 -> soname change). This
  is a separate release: v4.0.0 (SemVer: removing exported symbols is a
  breaking ABI change). v3.3.3 carries everything else.
  CONSEQUENCE for item 1: "incorporate sparsemap v5.7.0" becomes "review
  v5.7.0, report its defects upstream, and record that libumem no longer
  vendors it". If the user wants sparsemap kept, revisit.
- Sheaves article: map to libumem's depot. Linux's sheaf = libumem magazine;
  barn = depot (per-node) with full/empty lists; the patch adds a PARTIAL
  sheaf in the barn and lets a refill that needs k objects copy from the
  partial and then from full sheaves instead of taking from slabs under
  list_lock. libumem's analogue: umem_ptc_bin_refill / umem_cache_alloc_batch
  / PTC L2 magazine refill, which today pull whole magazines or go to the
  slab layer; the depot has no "partial magazine" and umem_ptc_mag_return
  drains a partial magazine back to the SLAB layer (umem_mag_drain) rather
  than keeping it. That drain is the direct analogue of "barn full list
  saturated -> flush to slabs". Candidate: keep one partial magazine per
  depot stripe and refill from it. Needs a design doc, a pre-fix measurement
  showing the drain cost, and the usual A/B + oracles. Measure before
  building.
