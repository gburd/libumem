## F1-F3 diagnosis DONE (@r8rss, 1f3be6e); fixes authorized (O11 lifted the bar)

Mechanisms (docs/results/r8rss/README.md), reproduced on lo and metal:
- F1 (RSS 2-2.7x glibc): free stock parked in stacked layers. On metal 1-4 KB
  t=192: free-only CONSUMER threads hold ~3.4 MB each (every PTC bin full +
  one full magazine per class, 36 % of RSS); the rseq per-CPU (272 MB) and
  classic per-CPU (217 MB) magazines both hold stock (54 %). Slab freelists
  <0.2 %. Control: UMEM_OPTIONS=tcache=0 cut RSS 29->19 MiB, no throughput
  change.
- O5 (umem_free_wrapper 37.6 %): a coherence miss on the size header the
  producer wrote on another core; the drop-in reads its in-band tag the same
  way (malloc.c:1064). 99 % of samples on the load after header->magic.
- F2 (flat t=192): libumem is already saturated at t=nproc; glibc is 5-6x
  BELOW libumem there and only catches up under oversubscription. Not a
  libumem defect. norseq +44 % x86 / +10 % arm at t=32 is unexplained (open).
- F3 (jemalloc 5.8-8.8x at 1-4 KB metal): object locality. libumem recycles
  anonymously; jemalloc returns a freed object to its allocating thread's
  arena. Producer memset ~10x costlier per op (perf share, not c2c-confirmed).

Fix plan (this round):
- F1-a @r8f1: bound free-only thread retention. A thread that only frees
  should not hold a full magazine + full bins per class indefinitely. Add a
  low-water trim on the PTC/magazine overflow slow path (NOT the fast path).
  class (i) footprint fix: needs a failing-before RSS test and a hotpath A/B
  inside the null (touches _umem_free-inlined code). Confirm the
  UMEM_OPTIONS=tcache=0 delta first as the target.
- F1-b @r8f1: confirm with a counter that umem_rseq_free_slowpath falls
  through to the classic layer (it allocates NO empty magazine: see umem.c
  3421 -- it pulls an EMPTY from the depot to RECEIVE, so the claim needs
  checking), then decide if the two per-CPU layers double-hold. ~6 lines if real.
- O5 @r8f1 (harness only): the bench API arm frees with the size the ring
  carries, removing the header read. Drop-in sizeless-free is class (ii),
  deferred with a ponytail note.
- F3 @r8f3: owner-routed magazine recycling is the real lever but large
  (class ii). This round: PROTOTYPE on a branch and A/B it at t=192 metal;
  only merge if it is a clear win with the fast path inside the null. Else
  document as the next perf lever.
- F2: no code; record that libumem saturates at t=nproc and glibc does not.
  The norseq t=32 regression is a separate open perf question.
