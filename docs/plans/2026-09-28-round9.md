# Round 9 (2026-09-28): F3 -- owner-routed magazine recycling

The remaining perf lever from the comparison. On metal at 1-4 KB, t=192,
jemalloc does 5.8-8.8x libumem's cross-thread-free throughput. The diagnosis
(docs/results/r8rss/README.md, F3/O4) attributes it to object LOCALITY, not
allocator code: libumem recycles freed objects anonymously (a consumer's full
magazine goes to a CPU depot stripe, then to whichever producer asks next),
while jemalloc returns a freed object to the arena of the thread that
allocated it, so the producer reallocates cache-warm lines. The producer
memset was ~10x costlier per op for umem -- but that 10x is DERIVED FROM PERF
SHARE, not confirmed with cache-miss counters.

## Gate order (do not skip step 0)

0. CONFIRM THE MECHANISM FIRST. Before any allocator change, run `perf c2c`
   (and/or `perf mem`/`mem_access` per op) on the metal t=192 1-4 KB prodcons
   for umem vs jemalloc. Show that umem's producer memset takes remote-HITM /
   remote-cache-line hits that jemalloc's does not. If the counters do NOT
   confirm cold/remote lines as the dominant cost, STOP: the fix would be
   optimizing a phantom. Report and reframe.

## Design (only if step 0 confirms)

Owner-routed recycling: tag a magazine (or its rounds) with the producing
CPU/node, and prefer same-owner magazines on refill. The fast path must stay
call-free and byte-identical when the feature is off:
- gate it behind a flag the fast path already loads (the UMF_* mask or the
  bin table), the same discipline as the T1/T8 hook (v3.3.3) -- a load+branch
  that is predicted-not-taken, never a new call on the hot path;
- off by default, or on only when it is provably free; the fast path A/B
  (hotpath_ab.sh, t=1 and t=8, both arches) must be INSIDE THE NULL with
  insn/pair +0.00, exactly as F1-a's revert required.
