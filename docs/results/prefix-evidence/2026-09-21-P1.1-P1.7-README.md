## Isolation

The shared working tree had other agents' uncommitted P1.2/P1.6 work in it
while this was being done, and `run-remote.sh` rsyncs the whole tree.  The
numbers below were therefore produced from a detached `git worktree` at exactly
the commits under test, rsynced to `~/libumem-fix` on each instance, so they
measure these fixes and nothing else.  An earlier mixed-tree run showed an
aarch64 `test_inspect_e2e.sh` failure that is NOT attributable to these fixes
(it also failed on x86_64 at the tests-only baseline commit, with
`AssertionError: expected 2 cached, got 1`).

## Note on `aligned_alloc` strictness

C11 leaves `aligned_alloc` undefined when the alignment is unsupported, and
glibc does not diagnose it (`aligned_alloc(3, 16)` returns non-NULL there).
libumem's interposer does diagnose it.  The test therefore requires NULL only
under `--strict` (used for the LD_PRELOAD run) and merely reports the system's
behavior in the control run, so the control is not asserting a non-portable
requirement against glibc.
