## O8 -- interior-pointer free: pre-fix consequence demonstrated

Test: test/unit/test_slab_interior_free.c (committed 1d32fc4, in make check).
Classifies a buffer by chunk start; interior free (buf + chunksize/2) must be
refused after 080ef6f (UMEM_SLAB_CHUNK) and was accepted before it
(UMEM_SLAB_MEMBER).

| build | ref | exit | RESULT |
|---|---|---|---|
| post-fix (current master) | ef1c151 (080ef6f is in it) | 0 | PASS -- interior free REFUSED (SIGABRT), control accepted |
| pre-fix | 080ef6f^ = 0a6089187baa | 1 | FAIL -- interior free ACCEPTED |

Pre-fix build note: 080ef6f^ built with `--disable-numa CFLAGS="-Wno-error"`
(Debian gcc 14 needs both); the test compiled with
`gcc -D_UMEM_INTERNAL -D_GNU_SOURCE -I. test/unit/test_slab_interior_free.c
./.libs/libumem.a -lpthread -lm -ldl -ldw`. The classifier under test is not
affected by --disable-numa or -Wno-error.

Pre-fix FAIL output verbatim (intel):

    control (free a chunk start): accepted, no abort -- ok
    interior free (buf + chunksize/2): ACCEPTED
    RESULT: FAIL (interior free accepted; no alias seen in 16 reallocs, but the free list took an interior pointer)

The two addresses (UMC_NODEBUG|UMC_NOMAGAZINE cache, bufsize 200,
chunksize 208):

    chunksize=208
    victim (keep[3])              = 0x7f05f0dffc40
    interior_target (victim+104)  = 0x7f05f0dffca8   <- pre-fix: accepted onto the free list

Post-fix, freeing 0x...ca8 aborts with UMERR_BADADDR because UMEM_SLAB_CHUNK
also requires (buf - slab_base) % chunksize == 0.

## O9 -- findleaks does not report rseq-resident buffers as leaks

Tests: test/integration/test_findleaks_rseq.c (+ _norseqsub variant, same
source), driven by test/integration/test_findleaks_rseq.sh; in make check TESTS.

The subtraction site is umem_inspect.c cached_set_build_cache(), rseq block
(guarded UMEM_RSEQ_AVAILABLE && umem_rseq_enabled).  Multi-thread batch churn
(BATCH=1024 > magsize, SZ=64) arms and fills cache_rseq[cpu]; workers are
QUIESCED (kept alive, not joined -- thread exit drains the PTC) while the main
thread reads findleaks JSON cached_skipped.

Negative arm: NOT norseq (norseq moves those buffers to the depot, which is
also subtracted -> proves nothing).  Instead a test-only library build with
only the rseq subtraction block compiled out (-DUMEM_FINDLEAKS_NO_RSEQ_SUBTRACT).
The default library is byte-identical.  default - norseqsub == rseq-resident
buffers, isolated from the depot/per-CPU subtraction present in both.

| arch | box | default cached_skipped | norseqsub | delta (rseq-only) | RESULT |
|---|---|---|---|---|---|
| x86_64 | intel-lo@r8cov | 4359 | 3192 | 1167 | PASS |
| aarch64 | arm-lo@r8cov | 4467 | 3475 | 992 | PASS |

A positive delta means the rseq block subtracted that many buffers that the
depot/per-CPU path did not -- i.e. the rseq subtraction is active and keeps
rseq-resident freed buffers out of the outstanding count.

Prior single-threaded attempt (commit 98bd847) parked nothing in rseq
(rseq only serves under multi-thread CPU contention; single-threaded
rseq_alloc=rseq_free=0, confirmed here via umem_dump_contention on intel:
`rseq_free=0` for umem_alloc_512).  Rewritten to multi-thread churn in ef1c151.
