# Bug Fixes and Improvements - April 7, 2026

## Critical Security Vulnerabilities Fixed

### 1. Integer Overflow in calloc() - CRITICAL
**File:** `malloc_interpose.c:358`
**Severity:** HIGH (Security vulnerability leading to buffer overflow)

**Problem:**
The calloc() implementation had a critical integer overflow vulnerability:
```c
size_t size = nelem * elsize;  // Line 358 - Can overflow!
```

The overflow check at line 396 happened AFTER the size was already used in lines 366 and 384 for the dlsym and calloc buffer paths. If `nelem * elsize` overflowed:

1. Line 358: size wraps to a small value
2. Lines 366/384: `(size + 15) & ~15` uses the overflowed value
3. Lines 367/385: Buffer bounds check passes with small value
4. Lines 370/388: memset writes with the original (large) size
5. Result: **Buffer overflow in static buffers**

**Attack Scenario:**
```c
// Attacker calls:
calloc(SIZE_MAX/2 + 1, 2);
// Expected: Huge allocation (overflows to ~0)
// Actual: Overflow check happens AFTER vulnerable usage
// Result: Buffer overflow in dlsym_buffer or calloc_buffer
```

**Fix:**
Moved overflow check to happen BEFORE any size calculations:
```c
/* Check for overflow BEFORE any size calculations */
if (nelem > 0 && elsize > 0) {
    if (SIZE_MAX / elsize < nelem) {
        errno = ENOMEM;
        return (NULL);
    }
}

size = nelem * elsize;
```

Also added secondary checks after alignment calculations to catch any overflow from the `(size + 15)` operation.

**Impact:** Prevents arbitrary code execution via heap buffer overflow.

## Non-Critical Bugs Fixed

### 2. Format String Mismatch in vmem_sbrk.c
**Files:** `vmem_sbrk.c:296, 310`
**Severity:** LOW (Incorrect output, no security impact)

**Problem:**
Used `%p` format specifier for `size_t` value:
```c
log_message("ignoring bad pagesize: 0x%p\n", heap_size);
```

**Fix:**
Changed to correct format specifier:
```c
log_message("ignoring bad pagesize: 0x%zx\n", heap_size);
```

**Impact:** Correct log output on all platforms.

### 3. Missing Function Implementations in test/qc.c
**File:** `test/qc.c:17`
**Severity:** LOW (Test framework completeness)

**Problem:**
- Functions `QCC_genArrayString()` and `QCC_genArrayStringL()` declared in qc.h but not implemented
- Wrong element size (`sizeof(long)` instead of `sizeof(uint8_t)`) in byte array functions
- Incorrect `return` statement in void function `QCC_label()`
- Compiler warnings suppressed with pragmas instead of fixed

**Fix:**
- Implemented missing array string generation functions
- Fixed element sizes in byte array functions (lines 396, 415, 421, 427)
- Fixed void return in `QCC_label()` function
- Removed all pragma diagnostic suppressions

**Impact:** Clean compilation, complete test framework.
